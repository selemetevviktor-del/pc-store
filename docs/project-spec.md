# Спецификация проекта «PC-Master» — Магазин ПК и комплектующих

## 1. Идея проекта и пользовательская проблема
**Пользователь:** Геймеры, ИТ-специалисты и обычные пользователи, желающие приобрести готовый ПК или собрать его самостоятельно из комплектующих.
**Проблема:** При самостоятельной сборке пользователи часто совершают ошибки в совместимости деталей (процессор не подходит к сокету, блоку питания не хватает мощности). Существующие конфигураторы сложны, а консультации в магазинах бывают неточными.
**Решение:** Веб-приложение со встроенным конфигуратором совместимости и интерактивным AI-помощником, который подсказывает оптимальные детали под бюджет и задачи пользователя, а также админ-панелью для оперативного управления остатками на складе.

## 2. Основная сущность (Product)
Каждая запись в системе представляет собой товарную позицию.

| Поле | Тип | Пример | Назначение |
| :--- | :--- | :--- | :--- |
| `id` | `string` | `gpu-1` | Уникальный идентификатор |
| `title` | `string` | `NVIDIA RTX 4070 Ti` | Название товара |
| `description` | `string` | `12GB GDDR6X, отличный вариант для 2K.` | Описание товара |
| `price` | `number` | `90000` | Стоимость в рублях |
| `category` | `string` | `Видеокарта` / `Готовый ПК` / `Процессор` | Категория товара |
| `status` | `string` | `В наличии` / `Заканчивается` / `Нет на складе` | Статус доступности |
| `isAvailable` | `boolean` | `true` | Логический флаг доступности к заказу |

## 3. Спроектированные страницы (Маршруты)
1. `/` — **Дашборд:** Сводная панель администратора. Статистика склада, количество дефицитных позиций, общая стоимость запасов.
2. `/catalog` — **Каталог товаров:** Список всех комплектующих и ПК с возможностью поиска и фильтрации по категориям.
3. `/product/:id` — **Детальная страница:** Подробные характеристики выбранного железа.
4. `/configurator` — **Конфигуратор ПК:** Интерактивный конструктор системного блока с проверкой совместимости деталей.
5. `/ai-chat` — **Чат с нейронкой:** AI-консультант для помощи в подборе конфигурации.
6. `/admin` — **Панель управления:** Страница добавления, удаления и редактирования количества товаров на складе.

## 4. Пользовательские сценарии
1. **Проверка дефицита товаров (Администратор):** Админ заходит на Дашборд, видит блок «Нужно дозаказать» (где остаток ≤ 2), определяет, какие видеокарты заканчиваются.
2. **Фильтрация комплектующих (Покупатель):** Покупатель заходит в каталог, выбирает категорию «Видеокарта», сортирует по цене и находит нужный графический чип.
3. **Консультация с AI (Покупатель):** Покупатель opens AI-чат, пишет «Подбери сборку для стримов за 120к», нейросеть анализирует базу данных и выдает список комплектующих.
4. **Сборка ПК в конфигураторе:** Пользователь поочередно добавляет материнскую плату, процессор и кулер. Система блокирует неподходящие блоки.
5. **Обновление остатков на складе:** Приехала новая партия процессоров. Админ заходит в панель управления, нажимает «Редактировать» у нужной позиции, увеличивает количество и сохраняет.

## 5. Границы первой версии
**Что входит:** Локальный запуск на Vite + TS, типизированная модель `Product`, массив из 12 mock-товаров, стартовый дашборд с расчетом аналитики склада методами массивов фронтенда.
**Что НЕ входит:** Подключение реальной БД, бэкенд-сервер, интеграция с API нейросети, стейт-менеджер Redux Toolkit (будет реализовано в ЛР 10).
